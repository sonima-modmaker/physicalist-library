# API для разработчиков

Physicalist Library предоставляет расчёты и серверный шаг для сущностей
сторонних модов. Основной пакет: `dev.physicalist`. Библиотека не знает
названий ваших ракет, машин или крыльев. Владелец модели создаёт адаптер,
который сообщает геометрию, состояние и правила повреждения.

Прежде чем подключать API, прочитайте
[установку зависимости](INSTALL_RU.md#подключение-как-зависимости-разработчика).

## Какие классы использовать

| Класс | Когда применять |
|---|---|
| `CompoundCollision` | Нужны точные контакты составной модели с блоком или другой моделью |
| `Aerodynamics` | Нужен один шаг аэродинамики внутри собственного контроллера полёта |
| `PhysicsProfile` | Нужны персональные коэффициенты движения и столкновений |
| `PhysicalistConfig` | Нужны общие значения из TOML |
| `PhysicsBody` | Хотите использовать готовый универсальный решатель |
| `PhysicalistSimulation` | Хотите выполнить один серверный шаг составного тела |
| `Hinge` | Нужен плавный шарнир с пружиной, сопротивлением и пределами |
| `ContactHinge` | Нужна реакция шарнира на столкновение |

API разделён так, чтобы можно было использовать **одну функцию** без замены
всей системы полёта. Create: The Air War, например, использует общие
вычисления, но оставляет у себя особое наведение и реакции деталей.

## Координаты и повёрнутые объёмы

`CompoundCollision.Box` — ориентированная коробка (OBB):

```java
new CompoundCollision.Box(center, axes, half)
```

- `center`: мировой центр детали (`Vec3`);
- `axes`: три взаимно перпендикулярные, нормализованные мировые оси детали;
- `half`: три **положительных** полуразмера по этим осям, в блоках.

Например, плоское крыло шириной 4 блока, толщиной 0,05 и длиной 1 блок
имеет `half = {2, 0.025, 0.5}`. Значение толщины `0` отключает контакт
для такого объёма; это удобно для временного исключения детали, но
обычному физическому крылу нужна положительная толщина. Массивы
`axes` и `half` передаются как есть, поэтому не меняйте их, пока идут
расчёты контакта.

```java
var wing = new CompoundCollision.Box(
    new Vec3(10, 80, 10),
    new Vec3[] {new Vec3(1, 0, 0), new Vec3(0, 1, 0), new Vec3(0, 0, 1)},
    new double[] {2, 0.025, 0.5}
);
var wall = CompoundCollision.box(worldBlockAabb);
var contact = CompoundCollision.contact(wing, wall);
if (contact != null) {
    Vec3 normal = contact.normal();
    double penetration = contact.depth();
    Vec3 point = contact.point();
}
```

`contact(a, b)` возвращает `null`, если объёмы не пересекаются.
Нормаль направлена **от второго объёма к первому**. `depth` — глубина
пересечения, `point` — приближённая точка контакта на первом объёме.
По нормали можно сдвинуть первое тело наружу, затем изменить его скорость.

`CompoundCollision.swept(before, after, obstacle)` ловит случай,
когда деталь пересекла препятствие между двумя подшагами, но в
конечном положении уже вышла с другой стороны. Метод рассчитан на
**поступательное** смещение; при большом чистом повороте добавляйте
подшаги и проверяйте актуальный `contact` в каждом положении.

Библиотека использует SAT — разделяющие оси двух OBB и их попарные
векторные произведения. Можно передать собственный тип с интерфейсом
`CompoundCollision.BoxView`, чтобы избежать копирования коробок.

## Один шаг аэродинамики

```java
PhysicsProfile profile = PhysicalistConfig.defaults();
Aerodynamics.Step result = Aerodynamics.step(
    velocity, angularVelocity, forward, up,
    wingArea, imbalance, stabilizers, bodyDamaged, profile
);
velocity = result.velocity();
angularVelocity = result.angular();
```

Аргументы:

- `velocity` — мировая скорость в блоках за тик;
- `angularVelocity` — угловая скорость, которую хранит вызывающий мод;
- `forward` и `up` — мировые единичные векторы осей модели;
- `wingArea` — относительная работающая площадь крыла (`0` без крыла,
  около `1` для целой модели);
- `imbalance` — знаковая асимметрия крыльев; знак задаёт направление крена;
- `stabilizers` — доля работающих стабилизаторов;
- `bodyDamaged` — признак повреждения корпуса;
- `profile` — общие или индивидуальные коэффициенты.

Результат вычисляет сопротивление, подъёмную силу, гравитацию и
угловые моменты. Тяга двигателя сюда **не** входит: добавляйте её
отдельно в своём контроллере. Если у вашего контроллера уже есть
гравитация, не применяйте её второй раз. Если вы делаете и ручной
аэродинамический шаг, и `PhysicalistSimulation.step`, получите
двойной расчёт: выберите один владеющий путь на тик.

### Индивидуальный физический профиль

Конструктор `PhysicsProfile` принимает параметры в следующем порядке:

```text
gravity, linearDrag, speedDrag, crossflowDrag, damageDrag,
liftFactor, maximumLift, restoringTorque, maximumRestoringTorque,
horizonTorque, maximumHorizonTorque, imbalanceTorque,
maximumImbalanceTorque, angularDamping, restitution, surfaceFriction,
maximumSpeed, contactSlop, minimumImpactSpeed, substepDistance,
maximumSubsteps
```

Все значения проверяются на конечность и допустимые диапазоны.
Например, `maximumSpeed` должен быть строго больше нуля,
`maximumSubsteps` — от 1 до 512, коэффициенты трения и отскока —
от 0 до 1. В `PhysicsBody.profile()` можно вернуть профиль,
сохранённый для типа вашей сущности. Не создавайте новый объект
`PhysicsProfile` на каждом подшаге: создайте его один раз или
используйте кэшированный `PhysicalistConfig.defaults()`.

Можно выбрать профиль по типу:

```java
@Override
public PhysicsProfile profile() {
    return isHeavyBomb ? HEAVY_BOMB_PROFILE : PhysicalistConfig.defaults();
}
```

`HEAVY_BOMB_PROFILE` в этом примере — ваш заранее созданный объект.
Библиотека не знает, что такое «бомба», и не навязывает ей специальную
формулу. Общий TOML меняет профиль по умолчанию; свой профиль имеет
приоритет для данной сущности.

## Универсальный серверный решатель

`PhysicalistSimulation.step(body)` вызывает аэродинамику, ограничивает
скорость профилем, разбивает движение на подшаги, обновляет положение
и поворот, проверяет блоки, выталкивает из контакта, применяет отскок
и трение, вызывает `onImpact` и записывает новую скорость.

Минимальный адаптер для простой коробки:

```java
import dev.physicalist.*;
import java.util.List;
import net.minecraft.world.entity.Entity;
import net.minecraft.world.phys.Vec3;

public final class ExampleBody implements PhysicsBody {
    private final Entity entity;
    private Vec3 angular = Vec3.ZERO;

    public ExampleBody(Entity entity) { this.entity = entity; }
    @Override public Entity entity() { return entity; }
    @Override public List<CompoundCollision.Box> collisionBoxes() {
        return List.of(CompoundCollision.box(entity.getBoundingBox()));
    }
    @Override public Vec3 forward() { return entity.getLookAngle(); }
    @Override public Vec3 up() { return new Vec3(0, 1, 0); }
    @Override public Vec3 angularVelocity() { return angular; }
    @Override public void setAngularVelocity(Vec3 value) { angular = value; }
    @Override public void rotate(Vec3 value, double fraction) {
        entity.setYRot(entity.getYRot() + (float) Math.toDegrees(value.y * fraction));
        entity.setXRot(entity.getXRot() + (float) Math.toDegrees(value.x * fraction));
    }
    @Override public void onImpact(int part, CompoundCollision.Contact hit,
                                   double normalSpeed) {
        // Ваш мод решает, повреждать ли предмет, воспроизводить ли звук и т. д.
    }
}
```

Это **учебный пример** с одной обычной AABB: он не вращает хитбокс
вместе с моделью и не показывает сетевую синхронизацию. Для ракеты
возвращайте несколько `CompoundCollision.Box` по деталям и обновляйте
их мировую ориентацию в `rotate`. Число деталей должно оставаться
постоянным внутри одного подшага; у потерянной детали можно
возвращать нулевой объём или перестраивать список между тиками.

Точка вызова в моде-владельце:

```java
if (entity.level() instanceof net.minecraft.server.level.ServerLevel) {
    PhysicalistSimulation.step(body);
}
```

Вызовите это **один раз за серверный тик**. Нативное движение сущности
в том же тике нужно отключить или заменить: два шага дают двойную
скорость, скачки и пропуски столкновений. Решатель выставляет
`noGravity` и `noPhysics`, потому что сам ведёт движение; ваш адаптер
должен согласовать это с жизненным циклом сущности. Клиентскую
интерполяцию, синхронизацию поворотов, сохранение и восстановление
угловой скорости, удаление объекта и прогрузку чанков выполняет
подключающий мод.

Если следующий чанк не загружен, универсальный решатель прекращает
движение текущего шага. Он **не** создаёт chunk ticket. Для дальних
быстрых ракет самостоятельно управляйте прогрузкой либо задайте
понятное правило выгрузки. Без этого объект может оказаться
в несимулируемом чанке.

Универсальный решатель пока обрабатывает блоки. Столкновения с
сущностями и возможность стоять на сложной модели добавляйте в
своём моде: можно использовать `CompoundCollision.contact` для
ваших коробок против `CompoundCollision.box(other.getBoundingBox())`.

## Шарниры

`Hinge` хранит положение `0…1` и скорость. Вызов

```java
hinge.step(appliedTorque, restPosition, stiffness,
           damping, resistance, maxRate);
```

прибавляет внешнюю нагрузку, тянет шарнир к `restPosition`,
учитывает сопротивление и ограничивает скорость `maxRate`.
После этого используйте `hinge.position()` для трансформации
детали и отдельно сохраняйте/синхронизируйте её в своём моде.

`ContactHinge.pressureDelta(normalSpeed, penetration, dt, used)`
возвращает долю хода от контакта. `used` — уже израсходованный
ход за текущий тик. `ContactHinge.target(angle, latched, touching)`
вычисляет цель при защёлке или возврате. Общие коэффициенты
находятся в секции `[hinges]` конфигурации.

## Сохранение, сеть и ответственность аддона

Библиотека не создаёт NBT-поля автоматически. Сохраняйте
угловую скорость, состояние крыльев, повреждения и индивидуальный
профиль там, где хранится ваша сущность. На сервере выполняйте
физику, на клиенте интерполируйте полученные положения. Если
клиент пытается выполнять тот же решатель независимо, со временем
возможны расхождения и «дёрганье» модели.

`onImpact` вызывается при превышении `minimumImpactSpeed`.
Если объект может взорваться, сначала проверьте предохранитель,
режим, точку удара и свои правила взрывателя; библиотека только
сообщает геометрию контакта. Прогрузка дальних чанков, реакция
других сущностей и внешние моды вроде Sable остаются на стороне
адаптера.

## Ограничения и проверка реализации

- Для каждого подшага `collisionBoxes()` вызывается до и после
  перемещения. Не загружайте JSON модели или текстуры в этом методе:
  подготовьте геометрию заранее.
- Детали с нулевым полуразмером пропускаются в `contact` и `swept`.
- Контактные оси должны быть нормализованы; иначе глубина
  пересечения и нормаль окажутся неверными.
- `swept` проверяет перенос между положениями, а не точную
  непрерывную траекторию быстро вращающегося крыла.
- Большое число деталей, блоков и подшагов влияет на TPS.
- Прямые расчёты можно проверить в `verification/LibraryPhysicsTest.java`.
  После этого проверяйте посадку, удар и синхронизацию в реальной игре.
