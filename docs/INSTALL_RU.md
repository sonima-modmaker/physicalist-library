# Установка, сборка и совместимость

Эта страница рассчитана на игрока, автора модпака и разработчика. Пожалуйста,
различайте **библиотеку Physicalist Library** и **мод, который использует её API**:
библиотека не создаёт предметы и не заменяет физику каждого объекта мира сама.

## Совместимость

| Требование | Значение |
|---|---|
| Minecraft | Только 1.21.1 |
| Загрузчик | NeoForge 21.1.219–21.1.251 включительно |
| Метаданные NeoForge | `[21.1.219,21.1.252)` |
| Java для сборки и запуска | 21 |
| `modId` | `physicalist_library` |
| Версия библиотеки | `0.1.0` |
| Create, Veil, Sable | Не требуются самой библиотеке |
| Лицензия исходного кода | GPL-3.0-only |

Диапазон в `neoforge.mods.toml` запрещает загрузку на версии ниже `21.1.219`
и на `21.1.252` или выше. Minecraft 1.21.2, 1.21.5 и другие версии здесь не
поддерживаются. Сборка на обеих граничных версиях проверена; это не равно
игровой проверке всех промежуточных патчей.

## Для игрока или сервера

1. Установите Minecraft 1.21.1 и совместимый NeoForge.
2. Скачайте `physicalist_library-0.1.0.jar` из релиза проекта либо соберите
   его по инструкции ниже.
3. Положите файл в папку `mods` нужного профиля Minecraft.
4. Установите мод техники, который использует библиотеку. Если это совместимая
   версия Create: The Air War, её JAR должен лежать рядом с JAR библиотеки.
5. Запустите игру и проверьте список модов: должны присутствовать Physicalist
   Library и подключающий мод.
6. Для сервера установите те же версии на сервер и на подключающиеся клиенты.

В Prism Launcher папка `mods` находится **в конкретном экземпляре**, а не в
общем каталоге лаунчера. Можно открыть её через меню экземпляра «Папка».
Рядом с библиотекой не требуется скачивать Create, Veil или Sable **ради самой
Physicalist Library**; отдельный мод с ракетами может требовать их по своим
правилам.

Не переименовывайте два различных варианта библиотеки так, чтобы они оба
оказались в `mods`. Оставьте одну версию JAR. Файл `-sources.jar` предназначен
для IDE и **не** кладётся в `mods`.

### Как проверить загрузку

В списке модов ищите `Physicalist Library`. Если игра сообщает
`Missing required dependency physicalist_library`, нужного JAR нет в этом
экземпляре или установлен не тот файл. Если библиотека есть, но объект
по-прежнему ведёт себя как обычная сущность, проверьте, подключает ли его
мод к API: одна библиотека не регистрирует физические объекты.

## Сборка из исходников

В корне проекта лежат Gradle Wrapper и официальный NeoForge MDK.
Для первой сборки нужен доступ к интернету: Gradle загрузит зависимости
NeoForge и Minecraft. После этого часть файлов кэшируется.

### Windows PowerShell

```powershell
cd C:\path\to\Physicalist-Library
.\gradlew.bat build
```

Проверка верхней границы совместимости:

```powershell
.\gradlew.bat build '-Pneo_version=21.1.251'
```

**Кавычки у `-Pneo_version=...` важны в PowerShell.** Без них PowerShell может
разделить аргумент, и Gradle решит, что ему передали название другой задачи.
Для возврата к основной версии после проверки:

```powershell
.\gradlew.bat build '-Pneo_version=21.1.219'
```

### Linux или macOS

```bash
./gradlew build
./gradlew build -Pneo_version=21.1.251
```

Результат находится в `build/libs/`:

- `physicalist_library-0.1.0.jar` — мод для игры;
- `physicalist_library-0.1.0-sources.jar` — исходники API для разработчиков.

Если нет установленного JDK 21, Gradle может получить toolchain автоматически
через конфигурацию шаблона, но для стабильной разработки лучше установить
JDK 21 и выбрать его в IDE.

### Проверки после сборки

`BUILD SUCCESSFUL` означает, что компилятор и сборочные задачи завершились.
Дополнительный тест `verification/LibraryPhysicsTest.java` проверяет три
свойства расчётов: инерцию, изменение подъёмной силы при сложенном крыле и
контакт тонкой детали с землёй на быстром перемещении. Он требует классы
Minecraft из NeoGradle и не заменяет проверку в запущенной игре.

CI в `.github/workflows/build.yml` собирает код на `21.1.219` и `21.1.251`
при каждом push и pull request. Для публикации релиза следует использовать
JAR, собранный на нижней поддерживаемой версии, и отдельно проверять его
загрузку на верхней.

## Подключение как зависимости разработчика

В NeoGradle-проекте можно положить собранный JAR в локальную папку `libs`
и добавить в `build.gradle`:

```groovy
dependencies {
    implementation(files("libs/physicalist_library-0.1.0.jar"))
}
```

Для запуска зависимого мода библиотека должна быть доступна **как отдельный
NeoForge мод**, а не только при компиляции. В `neoforge.mods.toml` добавьте:

```toml
[[dependencies.your_mod_id]]
modId="physicalist_library"
type="required"
versionRange="[0.1.0,)"
ordering="AFTER"
side="BOTH"
```

Замените `your_mod_id` на настоящий ID вашего мода. Если публикуете библиотеку
в Maven, вместо локального JAR можно подключить координаты опубликованного
артефакта. **Этот репозиторий пока не заявляет публичный Maven-репозиторий**;
пример с `libs` работает без него. `publish` в текущем шаблоне пишет только
в локальную папку `repo/` и сам по себе не загружает артефакт на GitHub.

Если работаете одновременно с исходниками библиотеки и зависимого мода,
поддерживайте совместимые версии API. При изменении `PhysicsProfile` или
сигнатуры методов заново соберите библиотеку, затем зависимый мод.

## Размещение файлов и структура проекта

```text
Physicalist-Library/
├── src/main/java/dev/physicalist/   API и расчёты
├── src/main/resources/META-INF/    метаданные NeoForge
├── verification/                  проверка физических инвариантов
├── docs/                          подробная документация
├── gradle/wrapper/                Gradle Wrapper
├── build.gradle                   зависимости и сборка
├── gradle.properties              версии и свойства мода
├── LICENSE, NOTICE                лицензия и происхождение кода
└── build/libs/                    готовые JAR после сборки
```

`build/`, `.gradle/`, рабочий мир `run/` и локальный `repo/` не включаются
в Git. Их появление после сборки нормально. Исходники и ресурсы проекта
хранятся в UTF-8.

## Обновление и откат

Перед заменой работающего JAR закройте Minecraft или сервер. Сохраните
предыдущие JAR-файлы отдельно. Затем замените библиотеку и мод, который
от неё зависит, **парой совместимых версий**. Если после обновления
загрузчик сообщает о несовместимом API, верните оба предыдущих JAR.
Конфигурацию можно сохранить, но при изменении имён или диапазонов параметров
сверьте её с новой версией и созданным файлом по умолчанию.

Установленный Create: The Air War уже использует расчёты этой библиотеки.
Чтобы удалить Physicalist Library из такой сборки, нужно также откатить
Create: The Air War на версию без этой обязательной зависимости.
