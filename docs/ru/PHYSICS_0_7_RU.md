# Physicalist 0.7 — крупное обновление физики

В исправлении **0.7.1 / Air War 5.02** свободные корпуса и объекты команды
`/ctaw_physics` идут прямо в Physicalist, без старого расчёта движения Air War.
Для проверки конкретного объекта: `/physicalist select look`, затем
`/physicalist info`. Строка показывает ID тела Rapier, его состояние и
`forces=Physicalist`. У управляемой ракеты в полёте силы двигателя и наведения
по-прежнему задаёт её контроллер; контакты и перемещение решает общая сцена.

Встроенные конструкции из блоков и тестовые регдоллы теперь работают в общей
сцене Rapier3D для каждого серверного измерения. Раньше тела рассчитывались
отдельными Java-шагами; теперь движок совместно решает контакты, трение, массу,
инерцию, сон тел, быстрые столкновения и ограничения суставов.

Это собственная интеграция открытого Rapier через Rust/JNI. Код, DLL, модели и
звуки MCS не перенесены. Из сравнения взят подход к организации физики, а не
весь боевой симулятор. Системы оружия, связи и тепловизора MCS сюда не входят.

## Как проверить

Установи один `physicalist_library-0.7.0.jar` в `mods`, Java 21, Minecraft 1.21.1
и NeoForge 21.1.219 или новее из ветки 21.1.x. Внутренний ID не меняется.
Готовая нативная библиотека приложена для Windows x86-64. При её недоступности
остаётся Java-физика, причину можно посмотреть в журнале.

- `/physicalist engine` — движок, количество тел, сон, пауза из-за чанков,
  кэш коллизий мира и время последнего шага. Для нового движка должно быть
  `Rapier3D 0.36.1 / f64 / ABI 1`.
- `/physicalist ragdoll` — отдельный манекен с твоим скином.
- `/physicalist ragdoll НикИгрока` — манекен игрока, который сейчас онлайн.
- `/physicalist stats start` и `/physicalist stats stop` — замер работы физики.
- Физическая палочка перетаскивает тела; колесо меняет расстояние;
  Tab с движением мыши поворачивает тело. F3+B показывает коллизии.

Проверь падение, стопку блоков, опрокидывание конструкции с тяжёлой стороной,
удаление опоры и сложенные руки регдолла. Части регдолла сталкиваются друг с
другом; небольшие зоны у креплений исключены только из контакта с туловищем,
чтобы плечо или шея не выталкивали собственный сустав.

## Что важно мододелам

Новый путь: один раз за серверный тик вызвать `NativeWorlds.enqueue(body)`.
Если он вернул `false`, использовать `PhysicalistSimulation.step(body)`.
Общий шаг выполняется после тика измерения. Не вызывай `flush` для каждого
объекта и не запускай оба решателя одновременно. Старый синхронный `step`
оставлен с Java-расчётом для совместимости: сторонний мод со своим циклом
физики нужно перевести на новый путь явно.

Адаптер `PhysicsBody` передаёт геометрию, оси, массу, угловую скорость и профиль.
`nativeGeometryRevision()` должен меняться при изменении формы, масштаба,
складывании крыла или отрыве детали. Перемещение всего корпуса не меняет
ревизию. Значение по умолчанию `-1` сравнивает геометрию каждый тик, что дороже.
Аэродинамика остаётся управляемой профилем; наличие нового движка не включает
самонаведение и не меняет модель ракеты автоматически.

Позиции считаются в блоках, скорости Java API — в блоках за тик, вращение —
в радианах за тик. На границе JNI скорости умножаются на 20, ускорения — на 400.
Нативные координаты используют двойную точность. Масса распределяется по
объёму частей, поэтому центр массы может отличаться от центра габаритов.

Коллизии мира кэшируются секциями 16×16×16. Полные соседние кубы объединяются;
ступени сохраняют собственные формы. Изменения блоков сбрасывают нужную секцию.
Непрогруженная область останавливает тело, вместо падения сквозь отсутствующий
мир. Прогрузку дальнего полёта и отрисовку за чанками задаёт сам мод транспорта.

Есть необязательный мост Sable: формы корабля, скорость точки и ответные силы.
Его совместимость нужно проверять на конкретной версии Sable. Полный API,
различия со старым режимом и ограничения описаны в [английском руководстве](../PHYSICS_0_7.md).
Это крупная смена движка, поэтому сравнивать производительность нужно замерами
в одинаковой сцене, а не обещанием неограниченного количества объектов.
